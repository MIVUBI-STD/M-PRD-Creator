# Documentation Router

Start with the topic, follow one domain router, then open only the canonical owner and affected consumers. Do not read all documents for reassurance.

| Requested responsibility | Authoritative domain |
|---|---|
| Product boundaries, approved requirement intake, PRD production, handoff, Production Assets and Voice | [Production Foundation](foundation/README.md) |
| Repository development, ownership, source priority, agent routing, decisions, current evidence | [Repository Knowledge](knowledge/README.md) |

Actual project-specific approval and generated deliverables live in separately authorized external/local project packages, not this public repository. Branch rules live in [GITHUB_RULES.md](../GITHUB_RULES.md); live source implementation lives in [kits/prd-creator/](../kits/prd-creator/README.md). A documentation link is a route, not a second source of authority.

**Authority:** current user instruction and approved project source outrank repository examples and historical evidence. Current source/contract owns behavior; generated material is derived. Stable `id` metadata identifies active documents independently of path.
